请为当前工作目录初始化项目约定文件 `AGENTS.md`。

## 怎么做

1. **先读后写**：动手之前把这个仓库看一遍——顶层目录与文件、构建配置文件
   （`pom.xml` / `build.gradle` / `package.json` / `pyproject.toml` / `Cargo.toml` / `go.mod`）、
   README、CI 配置，以及现有代码的目录结构与注释风格。
2. 把结论整理成 `AGENTS.md`，**用你的文件写入工具写到工作目录根下的 `AGENTS.md`**
   （不是子目录，也不是别的文件名）。
3. 写完后给用户一句话总结：写了哪些章节、哪几处是按仓库实际情况推断出来的。

## 写什么

这份文件是给「下一个来这个仓库干活的 AI 编码代理」看的常驻说明，只放**每次动手前都该知道的规则**，
不要复述代码、不要写成仓库介绍。按下面的骨架组织，**没有内容的小节直接删掉**，不要为凑格式写空话：

- **项目描述**：这是什么、给谁用、跑在什么环境（语言版本、框架与主要依赖）。
- **常用命令**：构建、跑全量单测、跑单个测试、格式化与静态检查。
  **从仓库里的构建文件与 CI 配置里读出来**，不要凭常见套路编造。
- **技术架构**：模块划分、依赖方向、关键目录各放什么。
- **关键不变量**：改一处会连带影响别处的规则（比如「某个类必须是唯一入口」这类）。
- **编码规范**：从现有代码里**观察**到的，而不是模板里的通用建议
  （缩进、注释语言与风格、命名、异常处理、文档注释要求）。
- **测试规范**：测试框架、命名约定、放置位置、能不能访问数据库 / 网络等外部资源。
- **Git 约定**：提交信息格式、分支习惯。
- **语言**：与用户沟通用什么语言。

## 硬约束

- **不确定的不要编**：从仓库里看不到的事实（团队习惯、外部系统地址、内部规范）宁可不写，
  或者明确标成「待补充」。
- **与仓库现有文档用同一种语言**（本仓库的文档大多是中文）。
- **只创建这一个文件**：不要顺手改构建配置、不要新建别的文档、
  不要执行会改动仓库的命令（提交、打标签、装依赖等）。
- 写文件会经过用户的权限与审批，被拒绝就如实告诉用户，**不要绕路**（不要改用 shell 重定向写文件）。
